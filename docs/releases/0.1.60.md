
- ⏱️ **The model's time limit is per round, not per task.** A task could keep the model working for 10 minutes in total (15 with the local model), tool calls included, and then it was cut: a Blender build of fifteen rounds hit that wall with the building half done, and a 3D job in ComfyUI was cut while ComfyUI was still finishing. The clock now starts when a round begins, pauses while that round's tools run (each connection has its own limit) and restarts on the next round, so a long task of many rounds is never cut for being long; a model that never answers still is. A task cut this way keeps the token usage and the per-round breakdown of the rounds that finished, so the Stats stay right.
- ⚙️ **Set in Config.** *Longest model answer*: minutes per round, 1 to 25 (`LLM_ROUND_TIMEOUT_MIN`). Empty keeps 10 minutes in the cloud and 15 with the local model. The per-task clock stays as a last resort, now 25 minutes for every provider; `HYDRA_LLM_TIMEOUT_MIN` in `.env` can only lower it. The troubleshooting page explains the new message ("The model gave no answer within N minutes (round M)").
