- 🔄 **The Update button hands over to a fresh supervisor.** On an install from source, pressing Update fetched and rebuilt the release but the process that runs the stack kept its old code and told the services the old version, so the app kept offering the same update; and the state file it left made `git status` dirty, which refused the next update. Now the stack is stopped and a new supervisor takes over (under systemd the service exits with code 3 and the unit starts it again; under a plain `pnpm serve` a new one starts in place; the desktop relaunches itself), the services report the version just installed, and nothing is left untracked in the clone. The first update that *reaches* this version still runs under the previous supervisor, so that one time the version label is stale until the service restarts.
- 🧰 **Tools stay loaded for the whole task.** With tools on demand, a tool left unused for three steps was unloaded to keep the definitions short. The per-round data showed the opposite effect: the tool list is the first thing in every request, and any change to it made the provider re-read the whole conversation at the full price (a Blender task with Opus 5.5 spent 512k of its 662k input tokens uncached). Loaded tools now stay for the rest of the task, and the model is asked to load in one call everything it will use.
- 🐧 **systemd unit, complete.** The service finds `uvx` (its PATH now includes `~/.local/bin`) and can write the caches of `uvx` and `npx`, so connections such as BlenderLab start under the service; a missing cache folder no longer keeps it from starting. The server-mode docs say which lines to add to a unit installed earlier.
- 🔧 **Self-update migrations on Windows.** The migration step of a self-update went through the shell and broke on a Node path with a space (`Program Files`), silently; it no longer does, and a failure is written to the update log.
