- 📅 **Approve a post once, publish it later.** Ask an agent to publish on X on Friday at 10 and it calls `x_post` with `publish_at`: the card you approve shows the final text, the files, the account and the time. Approved, the post goes into the Calendar as an action that carries that exact call, and at its time it is published as approved, with no model in between and no second question; the entry then shows the link (or why it failed), the card under the agent's reply shows the result, and Telegram tells you. Until then you can remove it from the Calendar; its text and agent cannot be changed, only its time. Nothing is scheduled unless it is the run of an `x_post` call you approved, the same rule a live post follows.
- ▶️ **The agent carries on after a decision you took early.** When you approved or rejected a held call while its task was still running, the agent never continued: the continuation was only tried at decision time, and the task was not finished yet. It is now tried again when the task completes, so the agent picks up with the outcome either way; the two paths cannot create two continuations.
- 📂 **A local connection can start in a folder of your choice.** A connection's entry may name the folder its program starts in (`cwd`), with placeholders filled in from its variables like the arguments; a catalog preset can carry it, the installed entry keeps it, the card shows it, and a folder that is not there is reported as the connection's error. The ComfyUI connection can thus work on your ComfyUI install instead of comfy-cli's default folder (the catalog preset will set it up).
- 🛡️ **A held call says why it was held.** A tool that always asks (`browser_act`, `create_skill`, a connection's `approve` class) held on a task that had read outside content was blamed on that content, to the agent, on the card and in Telegram. It now says the tool always waits for your approval; a sensitive call held because of outside content keeps naming where it came from.
