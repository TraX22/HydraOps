
- 🎮 **Unity, from the catalog.** The `unity` preset connects an agent to the Unity editor through Unity's own CLI (`unity mcp`), a native program with no `uvx`/`npx` form: the catalog now accepts it as a launcher, and **View** checks it is installed and, when it is not, shows how to get it. A preset may write `{{VAR}}` placeholders in a server's arguments (`--project-path {{UNITY_PROJECT}}`), filled in from the connection's variables when the server starts; a variable may be left empty after installing and its argument is then dropped, so the program uses its own default. Filling a variable in no longer marks the connection as hand-edited.
- 🛑 **The `approve` tool class.** Every call to such a tool waits for the user, whatever the task said and whatever the security mode, the way `create_skill` already behaves; *approve for the rest of the task* does not cover it. Meant for tools that run or write code inside an application (Unity's `eval`, `run_script`, `write_text_file`, `menu`). Shown in red in the classes legend and the tool list.
- 📁 **A connection's folders are a source of media.** A tool that saves into the application's own project (a Unity capture under `<project>/Assets/Screenshots`) stayed out of the chat, since the harvester looked only in the temp folder, the task's folder and `HYDRA_MEDIA_DIRS`. The absolute folders in a connection's arguments and variables now count too.
- 🔁 **A connected server with no tools is retried.** Unity's CLI answers without tools until the editor is open, and the connection stayed *connected · 0 tools* until HydraOps was restarted. Such a server is now retried once a minute like a failed one, counted from the connection itself; open the editor and the tools are there within a minute or two. A **Reconnect** button in Tools → Connections restarts one at once, hand-made connections included, and the state column says *Connected · no tools · retried automatically*.
