- ▶️ **The agent runs your project's commands, when you approve each one.** In a project, the agent can now install dependencies, run the tests, type-check and build, and read what came out. Every command waits for you: a card shows the exact command and the folder, and nothing runs until you approve it. There is no approving a whole task at once.
- 🖥️ **They run on your computer, with your tools.** Whatever the project is written in works with nothing to prepare. Nothing isolates a command from the rest of the machine, so the approval is the protection: read the command, and look at the files the agent changed that you have not accepted yet, which the card lists, because a command like `npm test` runs that code.
- 🌿 **Git stays in the tab.** A command that would commit, push or reset is refused before you are asked. A generator that starts a repository of its own inside your project no longer leaves it there as a nested one: its files stay as files of your project.
- 🎨 **An agent makes a new ComfyUI workflow from a request.** Ask for "a workflow that uses this checkpoint with this LoRA" and the agent builds it, checks every node, connection and model file against your ComfyUI, tries it once and saves it in your list of workflows, laid out left to right. A model you named that is not installed is reported, not swapped for another, and a saved workflow of yours is never replaced.
- 🔁 **An approved action no longer goes unreported.** When an action was approved while the agent was still writing its reply, the follow-up could be lost if the database was busy at that moment. It is now tried again.
- 📖 **In the manual.** Projects has a new Commands section; Add-ons explains how a workflow is created and saved.
