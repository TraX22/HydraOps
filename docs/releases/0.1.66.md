- ⏳ **A long ComfyUI generation is let go, not waited for.** On a modest GPU a workflow can take an hour, and the agent used to sit polling it until the task's own time limit cut it. Now `comfy_workflows` waits a couple of minutes at most and, when the job is still going, says so (running, or queued with N jobs ahead, and for how long): the agent tells you and ends its reply. Ask later whether it finished and it collects the result, or tells you how long it has been going and offers to cancel; the new action `cancel` interrupts a running job or removes a queued one. The last job each agent launched is remembered, so the question needs no id, even if the task that launched it was cut short.
- 🧩 **A continuation keeps the skills the agent had open.** When you decide on a held call, the task that carries on now receives the text of the skills the original task had opened, so the agent keeps following the same procedure instead of drifting into code it finds in the chat's history.
- ⚠️ **A task whose model never answered ends as failed.** A rejected key, a monthly spend limit reached, a model that does not exist: the task used to end as "completed" with an empty reply. Now it ends as failed, with the error kept, counted as such in the statistics and announced like a crash, so a cron's subscribers hear of it.
- 📂 **Only files a task made come into the chat from a connection's folders.** An asset a tool's answer merely named (a model a search listed) used to be brought in as a card; now only a file written while the task ran is.
- 🐧 **The systemd unit lets comfy-cli write its job records** (`~/.config/comfy-cli`), so the ComfyUI connection no longer fails right after ComfyUI took the job. Create that folder before the first start, as the unit's comment and the server-mode manual now say.
- 💬 The ComfyUI result tool tells the agent that you already see the files as cards under its reply, so it stops saying it has no way to attach them.
