- 🖥️ **The agent starts your project's development server and keeps it running.** Ask it to run the app and it starts the server, reads the address it printed, and can check the logs or stop it later. Starting one always waits for your approval, with the exact command on the card. A project can have up to three running, and you can see them, read their logs and stop them from the Projects tab.
- 🔑 **You choose which secrets files a server gets.** The agent works in a copy of your project, where files like `.env` are missing. In the project's settings you tick the ones a server needs. They are copied in only while a server runs, only if Git ignores them, and removed when the last server stops. The agent still cannot read them.
- 📜 **The agent reads the whole output of a command you approved.** It used to get the first 2,000 characters, so a failing test at the end of a long run was invisible to it. It now gets 16,000, and a very long command is shortened on the way back, not the output.
- 🔕 **A project can keep its approvals off Telegram.** Approving commands one after another made the phone buzz for each. A checkbox in the project's settings stops those notices for that project; the cards still wait in the app.
- 🧹 **A deleted project says when its copy could not be removed.** If a file was open in another program, the working copy stayed on disk with no word. Now you are told, and HydraOps removes it the next time it starts.
- 📖 **In the manual.** Projects has new sections for servers, secrets files and the Telegram switch; the skills page links to Unity's official skills; the README lists Projects, Git, Gmail and X.
